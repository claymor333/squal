# TUI Layout & Interaction Rework — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers-subagent-driven-development (recommended) or superpowers-executing-plans to implement this plan task-by-task.

**Goal:** Make the TUI not-broken and then feel like a tool: a real pane layout that cannot overflow, a multiline SQL editor, an interactive results grid (column sort + filter), the row editor reachable, delete/save/undo wired through the undo contract, a `?` help overlay, scoped errors, and safer connection close. Structural code (undo contract, streaming fetch, keyset, AI agent) is untouched.

**Architecture:** Everything lives in `internal/tui`. A new pure `layout` type derives pane rectangles from the window size; panes render inside their rect and expose viewport setters. Panes stay pure (mutate `connData`, emit `tea.Msg`s, return `tea.Cmd`s). `model.go` remains the shared file, owned by exactly one task at a time.

**Tech Stack:** Go 1.26, bubbletea v1.3, lipgloss (already in `go.mod`). No new dependencies.

**Parallelization:**
- **G1 [SEQ]** U1 layout shell — new `layout.go` + rework of `model.go` render and `mouse.go`. Everything renders inside these rects; it lands first.
- **G2 [PAR]** U2 (results interaction) + U3 (multiline editor) — disjoint files `results.go` / `editor.go`.
- **G3 [SEQ]** U4 bind the G2 keys in `model.go` + statusbar hints.
- **G4 [SEQ]** U5 row panel reachable + save/delete confirm — owns `model.go`, touches `rowpanel.go`/`writer.go`.
- **G5 [SEQ]** U6 history pane + undo — owns `model.go`, touches `history.go`.
- **G6 [PAR]** U7 help overlay + U8 statusbar rework + U9 AI panel polish — disjoint files `help.go` / `statusbar.go` / `aipanel.go`.
- **G7 [SEQ]** U10 integration + close safety + error routing — final `model.go` pass.
- `model.go` is owned in turn by U1 → U4 → U5 → U6 → U10, strictly sequential (tui DOC.md invariant).

## Global Constraints

- `gofmt` and `go vet` clean on every commit. No comments unless they add meaning.
- Panes stay pure-ish: mutate `connData`, emit `tea.Msg`s from `messages.go`, return `tea.Cmd`s. Never define a `tea.Msg` inline in a pane.
- The batch pump orders reads: don't read `Columnar` mid-fetch. Row-panel extraction reads the grid only after a `batchMsg` has landed.
- Structured writes go through the undo contract: `mutate.RowEditor` for before/after capture, `writer.record` for the action log. The UI says the verdict (undoable / logged-only).
- Live-DB tests `t.Skip` when the MariaDB (`127.0.0.1:3306`, `webstack`/`webstack`, scratch `squal_smoke`) is unreachable.
- Do NOT modify `fetch.go`'s `Columnar` layout; consumers depend on column-major.
- Conventional commits: `<type>(tui): <body>`.
